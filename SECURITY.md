# Security Policy

## Supported Versions

The latest minor release of Qasmith receives security updates. Earlier minor releases are not actively patched.

| Version | Supported |
| ------- | --------- |
| 0.10.x  | Yes       |
| < 0.10  | No        |

## Reporting a Vulnerability

**Do not open a public issue for a security vulnerability.**

To report a vulnerability privately:

1. **Preferred:** Use [GitHub private vulnerability reporting](https://github.com/quvly/Qasmith/security/advisories/new) if enabled on this repository.
2. **Alternative:** Email the security contact at the address below.

**Security contact:** _[Owner to provide a security contact email address and expected response time. Update this section before publishing.]_

### What to include

- Description of the vulnerability
- Steps to reproduce or a proof of concept
- Affected versions
- Any suggested mitigation

### Response timeline

The maintainer aims to acknowledge receipt within 72 hours and provide an initial assessment within 7 days. The exact response-time commitment will be confirmed by the project owner.

## Disclosure policy

- Reports are investigated in private.
- A CVE is requested when the vulnerability affects released binaries or the public installer workflow.
- Credit is given to reporters unless they request anonymity.
- Fixes are published together with a security advisory once a coordinated disclosure window has elapsed.
